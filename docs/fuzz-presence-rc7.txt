Protocol evidence:
https://github.com/CoffeeBrewer64/SE-Extended/blob/be815bbf435d8ece4514b390dc6dbbf2ee81c0aa/core/src/main/kotlin/me/rhunk/snapenhance/core/features/impl/spying/FriendTracker.kt#L169-L189
Repository commit: be815bbf435d8ece4514b390dc6dbbf2ee81c0aa

That source's presence decoder reads conversation field 6, repeated participant
field 4, participant key field 1 (uuid:session), and flags at participant field
2 -> field 1. It interprets bit 4 as typing/composition and bit 6 together with
bit 4 as speaking. The new implementation uses this interoperable schema; no
third-party implementation code was copied.

Compatibility caveat:
The source calls the voice state "speaking". There was no supplied Snapchat
14.17.1 iOS recording trace to independently confirm the mapping on that build.
These raw protocol bits are not the numeric SCCPresencePlatform typingState
enum and must not be applied to it. Actual keyboard-to-voice transitions and
notification delivery still require validation on the user's iPhone.
